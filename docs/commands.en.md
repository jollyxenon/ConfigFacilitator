# Command Reference

Use `cfgfc <command> --help` for the exact help generated by the installed binary. References may be canonical names or unique aliases; persisted references are always canonical.

## Shared behavior

### Project scope

`column`, `setting`, `mode`, `current`, `apply`, `refresh`, `status`, `reset`, and `revert` accept `-p/--project`. Without it, commands that need one Project use the PPID-scoped Project selected by `cfgfc use <Project>`. Explicit scope wins. `cfgfc use global` clears context. `sync --all` and `refresh --all` ignore context.

### Metadata flags

Create commands and resource `set` commands share:

- `--display-name <Text>`
- `--description <Text>` or `--description-file <Path|->`
- `--aliases <CommaSeparatedValues>` or `--clear-aliases`

The two description sources are mutually exclusive, as are the two alias controls. `--description-file -` reads all stdin bytes as the description. A `set` command requires at least one metadata flag.

### JSON and exit codes

Every non-help command accepts `--json`.

- Success: one object on stdout: `{"ok":true,"data":{...}}`
- Failure: one object on stderr: `{"ok":false,"error":{"code":"...","message":"..."}}`
- No ANSI or extra prose is emitted in JSON mode.

| Exit | Meaning |
| --- | --- |
| `0` | success |
| `2` | usage or argument error |
| `3` | missing, ambiguous, or conflicting resource/scope |
| `4` | invalid warehouse or resource data |
| `5` | confirmation or target-ownership refusal |
| `6` | filesystem, persistence, or transaction failure |

### Independent destructive controls

- `--yes`: confirms resource deletion, Column target deletion, or content deletion. There is no interactive prompt.
- `--cascade`: authorizes removal or repair of dependent references during resource deletion.
- `--force-targets`: authorizes reclamation only of affected recorded target paths when ownership has drifted or a target is occupied.

One flag never implies another. Removed `-f` and `--force` forms are invalid.

## Resource commands

### Project

```text
cfgfc project list
cfgfc project show <Project>
cfgfc project create <Project> [metadata flags]
cfgfc project set <Project> <metadata flags>
cfgfc project rename <Old> <New> [--force-targets]
cfgfc project delete <Project> --yes [--cascade] [--force-targets]
```

`project create` commits the complete Project structure, indexes, and runtime files. `global` is reserved.

### Column

All forms accept `-p/--project` or selected context.

```text
cfgfc column list
cfgfc column show <Column>
cfgfc column create <Column> [metadata flags]
cfgfc column set <Column> <metadata flags>
cfgfc column rename <Old> <New> [--force-targets]
cfgfc column delete <Column> --yes [--cascade] [--force-targets]
```

A new Column has zero target positions and an empty, usable Setting index.

### Column target positions

Indexes are zero-based.

```text
cfgfc column target list <Column>
cfgfc column target add <Column> --dir <Directory> (--name <Name> | --name-from-setting)
cfgfc column target set <Column> <Index> [--dir <Directory> | --clear-dir] [--name <Name> | --name-from-setting]
cfgfc column target delete <Column> <Index> --yes
```

Adding or deleting a position resizes every Setting override in lockstep. `--name-from-setting` derives the target name from each Setting's canonical name.

### Setting

Every form requires `-c/--column` and accepts `-p/--project` or selected context.

```text
cfgfc setting list -c <Column>
cfgfc setting show <Setting> -c <Column>
cfgfc setting create <Setting> -c <Column> --kind <file|directory> [metadata flags] [content source]
cfgfc setting set <Setting> -c <Column> <metadata flags>
cfgfc setting rename <Old> <New> -c <Column> [--force-targets]
cfgfc setting delete <Setting> -c <Column> --yes [--cascade] [--force-targets]
```

Creation accepts at most one content source:

- `--from <Path>` copies a regular file for `--kind file` or a regular directory tree for `--kind directory`.
- `--stdin` reads exact stdin bytes and is file-only.
- `--text <Text>` stores exact argument bytes without adding a newline and is file-only.
- No source creates an empty file or directory.

Imports reject symlinks and special filesystem objects.

### Setting target overrides

```text
cfgfc setting target list <Setting> -c <Column>
cfgfc setting target set <Setting> <Index> -c <Column> [--dir <Directory> | --inherit-dir] [--name <Name> | --inherit-name]
cfgfc setting target reset <Setting> <Index> -c <Column>
```

Directory and name inheritance are independent. `reset` restores both components to Column defaults.

### Setting content

Every form requires `-c/--column` and accepts `-p/--project`.

```text
cfgfc setting content list <Setting> -c <Column>
cfgfc setting content read <Setting> [RelativePath] -c <Column>
cfgfc setting content write <Setting> [RelativePath] -c <Column> (--from <RegularFile> | --stdin | --text <Text>)
cfgfc setting content mkdir <Setting> <RelativePath> -c <Column>
cfgfc setting content move <Setting> <OldPath> <NewPath> -c <Column>
cfgfc setting content delete <Setting> <RelativePath> -c <Column> --yes
```

For a file-backed Setting, omit `RelativePath` for read/write. For a directory-backed Setting, read/write needs a relative file path; `list`, `mkdir`, `move`, and `delete` operate only within the Setting root. Paths must be clean, non-absolute, traversal-free, and contain no symlink component. Human `read` writes exact bytes; JSON `read` uses UTF-8 text or explicit base64 fallback.

### Mode and selections

```text
cfgfc mode list
cfgfc mode show <Mode>
cfgfc mode create <Mode> [metadata flags]
cfgfc mode set <Mode> <metadata flags>
cfgfc mode rename <Old> <New> [--force-targets]
cfgfc mode delete <Mode> --yes [--cascade] [--force-targets]
cfgfc mode column list <Mode>
cfgfc mode column set <Mode> <Column> --strategy <cover|increment|none|full> [--setting <Setting> ...] [--force-targets]
cfgfc mode column delete <Mode> <Column> [--force-targets]
```

Repeat `--setting` one or more times for `cover` and `increment`. Do not supply it for `none` or `full`. Deleting a Mode selection is not resource deletion and does not use `--yes`.

Changing a Mode that the Current follows replans the Current in the same transaction; see [Current state](#current-state-temporary-mode). Deleting a Mode keeps the Current's columns and mappings and clears only its `relation`; renaming a followed Mode updates the Current's `originMode`. `--force-targets` authorizes reclamation only of affected recorded drifted or occupied targets.

## Current state (temporary Mode)

(Current) is the active configuration state, modeled as a temporary Mode. Its `columns` are the authoritative selections, its `mappings` are the planned links (under `increment` they also keep the cumulative baseline), and its `relation` describes only the relationship to a named Mode. `relation.kind` has two kinds: `following` (the Current follows a named Mode; later changes to that Mode's selections or `sync` replan the Current from the Mode's latest selections) and `detached` (the Current has forked; Mode changes do not affect it and `refresh` replans only from its own columns). No relation means the Current is independent.

```text
cfgfc current show [-p <Project>]
cfgfc current column list [-p <Project>]
cfgfc current column set <Column> --strategy <cover|increment|none|full> [--setting <Setting> ...] [-p <Project>] [--force-targets]
cfgfc current column delete <Column> [-p <Project>] [--force-targets]
```

`current show` prints the relation, per-Column selections, and planned mappings. Editing the Current directly (`current column set/delete` or a Web UI write) turns `following` into `detached` while keeping `originMode`. Deleting a followed Mode clears only `relation` and keeps columns and mappings; renaming a followed Mode updates `originMode`.

## Context, status, apply, and maintenance

### `use`

```bash
cfgfc use OpenCode
cfgfc use global
```

A canonical Project is stored for the current PPID even when an alias was entered. This is convenience state, not isolation or authorization.

### `status`

```bash
cfgfc status
cfgfc status -p OpenCode
cfgfc status --json
```

Without effective Project scope, status summarizes all Projects. With scope, it reports the Current state — relation kind, origin Mode when following, per-Column coverage, planned mappings, unresolved references, and incomplete transaction diagnostics. Human output shows `Current: following (Mode) [...]`, `Current: detached (Mode) [...]`, or `Current: independent [...]`; JSON exposes the same data under the `current` field with `columns`, `relation`, and `mappings`. It is read-only and does not recover transactions.

### `apply`

```bash
cfgfc apply mode <Mode> [-p <Project>] [--force-targets]
cfgfc apply column <Column> <Setting>... [-p <Project>] [--force-targets]
```

`apply mode <Mode>` makes the Current follow that Mode and replans its mappings from the Mode's latest selections. `apply column <Column> <Setting>...` sets the Current to an independent state containing exactly the given Settings. Unresolved resource references block planning before target changes.

### `refresh`

```bash
cfgfc refresh [-p <Project>] [--force-targets]
cfgfc refresh --all [--force-targets]
```

`refresh` replans the Current from current metadata. A `detached` or independent Current is replanned from its own `columns`; a `following` Current is replanned from the origin Mode's latest selections. `--all` refreshes every Project with active Current state and cannot be combined with Project scope. Byte-only content edits do not require refresh because managed links still point to the same source. The removed `--column` flag is invalid.

### `sync`

```bash
cfgfc sync
cfgfc sync -p <Project>
cfgfc sync --all
```

Sync is the boundary for Git, file-manager, or direct valid JSONC changes. It discovers new resources and immediately removes metadata for indexed Project directories, Column directories, and Setting files/directories whose sources disappeared. It does not recreate sources or implicitly cascade Mode selections, current/history runtime records, or PPID context; later `apply` or `refresh` fails before target changes when those references cannot resolve. `sync --prune` and `sync --prune --yes` are unsupported. Recreating a former source path does not restore deleted metadata. `--all` and `-p/--project` are mutually exclusive. The removed `-a` shorthand is invalid.

Each Project commits in its own transaction. `sync --all` handles every Project independently: a failed Project rolls back its own changes, successful Projects keep theirs, and the command reports the summary with failures listed. Missing Project/Column/Setting index entries are rebuilt from the filesystem with canonical names and minimal default metadata; a missing `ModeIndex.jsonc` has no directory source and is rebuilt empty. A missing `current_state.json` is rebuilt as an empty Current and the old `history.log` is deleted. A legacy-format or corrupted `current_state.json` keeps only that Project unusable (other Projects are unaffected) until the user deletes it and runs `sync` again. `sync` also replans a `following` Current from the origin Mode's latest selections.

### `completion`

```bash
cfgfc completion bash
cfgfc completion zsh
cfgfc completion fish
cfgfc completion powershell
```

The command writes a completion script to stdout. Generated completion includes canonical Project, Column, Setting, and Mode names plus aliases where the current scope can be resolved.

### `reset`, `revert`, and `root`

```bash
cfgfc reset [-p <Project>] [--force-targets]
cfgfc revert [-p <Project>] [--force-targets]
cfgfc root [Path]
```

`reset` removes current managed mappings but preserves warehouse resources. `revert` restores only the previous snapshot; it is not arbitrary history checkout.
`revert` rewinds only the Current state (columns/relation/mappings), never resource metadata or content. `root <Path>` persists later root resolution without migrating, copying, or initializing warehouse contents.

### `web`

```bash
cfgfc web [--port <Port>]
```

`web` serves a local Web UI on `127.0.0.1` (default port `38031`). The frontend is embedded in the single binary and needs no separate install or network access; the browser talks to the backend through `/api/snapshot`, `/api/command`, and `/api/preview`. In a selected Project, the UI can create Column, Setting, and Mode resources and edit existing Column/Setting Index metadata and targets. Canonical Column/Setting renames are separate transactional actions that update sources and references. New Columns have zero targets, new Modes have no selections, and Web-created Settings support empty directories or UTF-8 file content only. Write commands carry the warehouse-wide `revision`; a stale revision returns HTTP `409` without partial changes. If the port is already in use, the command fails with a persistence error instead of silently picking another port. Press Ctrl-C to exit.

## Old-to-new migration

| Removed form | Current form / guidance |
| --- | --- |
| `cfgfc new -p P` | `cfgfc project create P` |
| `cfgfc new -p P -c C` | `cfgfc column create C -p P` |
| `cfgfc new -p P -m M` | `cfgfc mode create M -p P` |
| manual Setting file/directory creation | `cfgfc setting create S -c C --kind file|directory` with `--stdin`, `--text`, or `--from` |
| manual Setting content editing | `cfgfc setting content read/write/mkdir/move/delete` |
| manual target-array editing | `cfgfc column target ...` and `cfgfc setting target ...` |
| manual Mode selection editing | `cfgfc mode column set/delete ...` |
| `cfgfc switch P` | `cfgfc use P` |
| `cfgfc switch global` | `cfgfc use global` |
| `cfgfc list` | `cfgfc status` for runtime state; `project/column/setting/mode list|show` for resources |
| `cfgfc list -p P -c C` | `cfgfc setting list -p P -c C` or `cfgfc column show C -p P` |
| `cfgfc list -p P -m M` | `cfgfc mode show M -p P` or `cfgfc mode column list M -p P` |
| `cfgfc apply -p P -m M` | `cfgfc apply mode M -p P` (Current follows the Mode) |
| `cfgfc apply -p P -c C -s A,B` | `cfgfc apply column C A B -p P` |
| `cfgfc update -p P` | `cfgfc refresh -p P` |
| `cfgfc update -c C` | `cfgfc refresh` (single-Column refresh was removed; refresh replans the whole Current) |
| `cfgfc update --all` / `-a` | `cfgfc refresh --all` |
| `cfgfc sync -a` | `cfgfc sync --all` |
| `-f` / `--force` | `--force-targets` only where target reclamation is intended; add independent `--yes` and/or `--cascade` when required |
| disappearance retained metadata during sync | current sync removes filesystem-backed Index metadata immediately; it does not cascade references or restore deleted metadata |
